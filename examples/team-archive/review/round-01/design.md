# 候选设计与依据

本文件是模拟用户演练第一轮的设计记录，状态为待澄清。

## 已说明

Python、SQLite、本地多层目录、负责人管理范围、审批可撤销、两项检查、有限处理名额、内容可修改、开发者图的拖动和逐层展开，以及真实参数和等待原因的解释。

## 尚未定义

目录权限继承；审批对象和审批者；多条审批的组合；归档的持久效果；两项检查的通过标准、并发和容量；审批/内容变化时旧运行的处理；等待后的恢复方式。

## 本轮建模选择

- 以业务依赖网建模，保持步骤、判断、资料和资源的不同身份。
- 选择 `archive_commit` 为局部图锚点，深度 1。范围外的目录输入、名额、撤销和内容变化保留原边界关系。
- 不把两项检查画成已确认的并发执行，不给尚未确认的汇合条件写执行规则。
- `processing_slots` 在候选行为图中为数据节点，在需求网中为资源概念。确认执行规则后，同身份接入实际资源和活动声明；当前没有资源执行模型。
- `source_files` 为空，执行节点的 `binding_status` 为 pending。依据 Skill 的 continuous-development.md，开发前候选图可以保留稳定身份与待绑定说明。没有宣称通过执行模型校验。
- 没有审批引擎或其他实现选型决定。

## 后续函数与参数需要覆盖的位置

以下是待定义的映射位置，不是现有函数、已授权业务规则或白盒验收：

| 节点 | 未来需明确的输入 | 未来需观察的真实结果 |
|---|---|---|
| scope_check | 操作者、资料所在目录、管理关系与目录关系 | 每项关系读取、路径、范围判断 |
| approval_check | 目标对象、审批候选、适用版本和撤销状态 | 实际执行的每条子判断及汇总结果 |
| content_check | 本次运行身份、资料内容及其版本、检查参数 | 函数入出、执行状态、检查结果 |
| index_check | 本次运行身份、索引输入及其版本、检查参数 | 函数入出、执行状态、检查结果 |
| processing_slots | 资源作用域、容量、占用实例 | 等待原因、占用与实际归还 |
| archive_commit | 本次运行和对象、已确认的前置事实 | 事务成功后可独立读取的归档效果 |

待本轮及必要后续问题得到回答后，再建立独立 acceptance、whitebox 参数契约、sync 配置与最小失败场景。此时运行 `whitebox plan`，随后按 begin → 编码/inspect → verify → accept → check 推进。

# 类型、规则和运行记录

本页区分现有实现和接入约定。图服务于开发者检查实现，不要求业务代码改用某一种编程框架或规则引擎。

## class、实例和调用

三者不能共用一个身份。参考 [UML 的类与实例规范](https://www.omg.org/spec/UML/2.5.1/)，采用以下关系：

| 内容 | 含义 | 图中位置 |
| --- | --- | --- |
| 类 / 类型 | 字段和方法的定义 | 所属业务区域内的类型节点，可展开关键方法和字段 |
| 实例 | 某个类型的具体对象 | 挂在类型上的运行事实；默认显示被选中的对象 ID 与关键字段 |
| 调用 | 方法执行了一次 | 带 call ID、接收者 ID、输入、返回和起止事实；不能用方法节点数量冒充调用次数 |
| 业务对象 | 订单、文档等有稳定业务 ID 的对象 | 可对应数据库条目，也可由多个代码对象共同实现 |

业务概念到类是多对多映射；类到对象是 `instance_of`；类到方法是定义归属；调用到对象是接收者关系；继承、组合、引用、调用必须分别标型。不要把继承画成运行调用。一个对象被多个模块引用时保留同一身份，使用已有共享入口；不要复制对象状态。

默认不展开全量对象堆。选定业务对象后，下钻查看这一对象的关键字段和相关调用。多对象同时执行时按对象、attempt 和 call 分开；旧值不可跨对象或跨运行继承。数据库行 ID、进程内对象 ID 和业务 ID 必须说明映射来源。禁止把进程内地址作为长期业务身份。

**当前边界：**Python 静态分析器识别 class、方法和可解析调用；视图主要生成关键函数/参数节点，运行事件已有 entity、attempt、call 身份。尚未实现通用对象堆采集，也没有将任意 Python class 与对象实例自动完整呈现。上表是继续接入时的表达约定，不能据此声称现有 schema、所有语言适配器或实例关联都已支持。扩展必须同时更新模型校验、采集身份、视图和跨实例测试。

## 规则结构与具体求值

可以把规则画成稳定的关系图，但图形的边必须有可执行含义：

- [DMN](https://www.omg.org/dmn/) 的决策需求图区分输入、决策和业务知识。适合表达“需要哪些数据和子判断”，决定条件可继续展开成决策表或表达式。关系图本身不等于完整的执行表达式。
- [OpenFGA](https://openfga.dev/docs/concepts) 和 [SpiceDB schema](https://authzed.com/docs/spicedb/concepts/schema) 区分对象类型、关系、权限表达式和具体关系事实。直接关系、组成员、关系继承、并集、交集、排除、递归及条件应保留各自语义。不能把所有关系都理解为可传递。
- [SHACL](https://www.w3.org/TR/shacl/) 区分约束图与数据图，适合数据结构约束和验证；它本身不是授权服务。研究中的 [Semantic DMN](https://arxiv.org/abs/1807.11615) 讨论将决策与领域知识结合，适合作为抽象层连接的参考，不能代替运行证据。

一次求值 = 请求（谁、对什么、做什么）＋有版本的事实＋上下文（时间等）＋实际经过的规则＋结果及实际效果。场景不只是“一组数据”：同一关系数据在不同操作、时刻、版本或提交边界下可能得出不同结论。

默认使用**同一规则图上的实例绑定**：在节点旁显示本次对象、字段值、条件结果，边显示本次实际使用的关系和数据。无需为每次请求复制整张权限图。需要分析递归、继承、多组来源、排除或撤销时，再展开本次的最小关系证据子图，并标明它省略了哪些上下文。关系事实确实构成图，并不意味着应常驻显示全库实例图。

允许结果需要相应支持路径；拒绝结果可能来自缺少关系、显式排除、条件失败或查询未完成，不能统一画成红色路径，也不能把超时当拒绝。[SpiceDB 的 Check tracing](https://authzed.com/docs/spicedb/modeling/validation-testing-debugging) 可提供真实遍历依据，但有额外开销。若引擎只返回布尔值，显示“未采集解释路径”，不要由 AI 补出执行路线。

本仓库当前记录的是示例自身的条件与关系读取；尚未接入通用 DMN、OpenFGA 或 SpiceDB 解释适配器。

## 采集和显示分开

| 方式 | 开始记录时确定 | 回放时可以改变 |
| --- | --- | --- |
| 全部核心事件（默认） | 保存所有已接入探针的白名单字段 | 业务、状态、函数等视图；展开层级；筛选条件 |
| 仅选中区域 | 固定所选节点、后代、祖先及完整状态版本的必要边界 | 对已保存事实继续筛选、下钻；范围外无法补录 |

“全部”不等于全变量、每行代码或所有普通调用。只有接入过的探针才有运行事实。区域模式的边界清单写入记录的 `capture`；边界状态可能包含并发活动与共享资源，以解释等待和汇合，但不因此采集圈外全部函数载荷。界面明确提示局部记录。

示例接口：`POST /api/recordings/start`，请求 `{"scope":{"mode":"focused","roots":["content_check"]}}`。不传 scope 或 mode 为 all 则记录全部核心事件。停止、容量上限和保存失败均恢复原默认采集。只读图和回放不发送业务命令。

原始事件不可随缩放删除。显示步骤由**当前可见层级与类型**决定，不依赖偶然的像素大小：业务视图合并内部值事件，函数视图呈现已采集调用与参数变化；逐事件模式可查看原始事件。展开后重新组织显示步骤，保留游标的原始事件身份。没有实际采集的调用不能靠静态边补出来。

每个显示步骤保留其原始事件区间、状态/值的 before→after 和多次中间变化。首次未采集旧值显示“未记录”，不可默认为 0 或空字符串。调用参数按 producer/entity/attempt/node/call/方向/字段分开，不跨调用或运行拼接。业务层显示主判断、实际活动与资源变化，不把逐条对象求值时的参数差异当成同一对象状态改变。未提供 call 身份的旧记录只能使用其已有身份范围，不能证明跨对象归属。回放结束的快照只在最后使用。

线上的传递按调用、输入/返回、判断、状态迁移、资源占用和汇合分别标色、标型、显示值或动作。静态结构、共享引用和仅时间相邻的事件不得播放成实际传递。

## 采集放在哪里

当前参考实现：`bo_record` / `bo_emit` → 白名单字段与身份 → 有界队列 → **同进程后台线程** → 事件文件；记录模块另有同进程后台线程保存区间。它不是独立采集进程，也不是零开销。范围判断在可延迟载荷构造前执行，关闭或故障不能改变业务结果。计算字段、序列化、队列与调度仍有成本，正式服务需按实际负载测量。

可根据项目选用以下机制：

| 机制 | 适合采集 | 不能自动提供 |
| --- | --- | --- |
| 显式探针 / 中立观测端口 | 业务判定、选定参数、权威读取、提交事实 | 未接入的变量或外部状态 |
| [Python sys.monitoring / PEP 669](https://peps.python.org/pep-0669/)（3.12+） | 选定代码的调用、返回和异常事件 | 业务含义、可靠的任意变量快照；回调仍在进程内 |
| [OpenTelemetry agent / sidecar collector](https://opentelemetry.io/docs/collector/deploy/agent/) | 接收应用 SDK 或自动插装的遥测，独立处理与导出 | 凭空观察应用未暴露的业务条件；应用端仍有成本 |
| [py-spy](https://github.com/benfred/py-spy) | 进程外抽样的调用栈和性能热点 | 保证不漏的逐次调用、每次状态变化和权限依据 |

可以将文件写入和导出迁移到独立 collector，但业务程序仍负责产生准确事实。不能为了“无侵入”用抽样堆栈替代确定性的状态记录。本版未增加独立 collector。

## 源码和验收约定

业务层只调用项目自有的中立端口。观测专用方法必须用 `bo_`，类用 `BO`；示例为 `trace.bo_record(...)` 和 `events.bo_emit(...)`。适配器置于 integrations/bo_*，运行库置于 observer_runtime 或 observer_generated/runtime。领域函数、真正的状态机和业务变量使用正常领域名，不放进可删除观测目录。旧端口别名仅用于兼容。

开发者可以自由修改业务实现；AI 每轮同步保留稳定节点 ID、更新符号绑定、字段类型、探针和白盒预期，执行原有变更检查。改名、重构或删字段造成的映射失效必须报告，不能靠图缓存继续展示旧绑定。普通人工编辑不会被 Skill 自动监听。

必须测试：局部采集跳过圈外载荷、必要边界完整、停止/失败恢复；业务结果在关闭/过滤/异常时一致；业务与函数视图步骤不同但原始事件不变；中间值与跨实例/运行隔离；真实关系依据才能驱动动画；批注/核心标记按稳定节点身份保存，不改变源码或业务权限。

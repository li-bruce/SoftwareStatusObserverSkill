# 模拟需求方的原意（开发会话开始前固定）

这是测试协调者拟定的合成用户意图，不代表真实用户新增了以下业务规则。开发会话只能获得最初需求，以及它提出必要问题后得到的对应答案。该文件不作为开发输入。

## 最初输入

构建一个简单的项目管理系统，用户创建项目后，可基于已有项目派生新项目，并配置项目间的数据流转关系；项目派生与关系配置须具备相应权限，数据流转须符合预设的项目类型及端口规则。

## 需要问到时才给出的答案

- 创建：已登录的用户可以创建项目，创建者是该项目所有者。演示可以选择几个固定用户，不要求真实账号注册或登录服务。
- 派生：保留来源项目 ID；同类型新项目、空数据、新创建者为所有者。数据、授权和数据连接均不复制。来源项目所有者或获得该项目 derive 权限的用户可以派生。
- 配置关系：操作者必须同时拥有源、目标项目的 connect 权限，项目所有者在自己的项目上自然具备这项权限。授权以测试数据提供；不增加权限管理页面或审批流程。
- 类型与端口是固定配置：采集项目有 records 输出（dataset/v1），处理项目有 records 输入（dataset/v1）及 result 输出（result/v1），报告项目有 result 输入（result/v1）。只允许采集到处理、处理到报告，且输出到输入、端口存在、数据格式标识相同。
- 流转：首版要实际传一份 JSON 数据；由有两端 connect 权限的用户手动执行一次，将源端口当前值复制到目标输入。配置连接本身不传数据，也不自动运行处理项目中的算法。输入值可以来自固定样例。每次执行重新检查权限、项目类型和端口规则；失败不写目标值。数据按给定 JSON 值复制，不增加业务内容校验规则。
- 派生关系与数据连接各自独立。前者说明来源，后者说明允许的数据路径；没有自动传递的授权或连接。
- 不要求调度、审批、通知、版本历史、自动重试、复杂工作流或租户管理。只有对以上内容的歧义才澄清；技术实现由开发助手选择。

## 后续迭代（初版完成后再提出）

派生新项目时允许指定另一个已有项目类型，未指定仍用来源类型；仍然是空项目，不继承连接、数据或授权。请同步更新图和检查。

## 评价方式

检查实际问答是否区分来源关系与数据关系、权限与端口规则，反例是否只检验已有表述的理解，以及是否在范围清楚后停止追问。对未问到的语义记录遗漏，不在后台补答案。实现、图和检查应明确区分合成用户确认、技术选择、静态证据与运行事实。保留真实工具返回与失败，不预先声称全部通过。

# 审查口径

每项判定必须指向实际问答、文件或运行结果。不存在的证据记为未验证。

1. 触发：独立会话实际读取当前安装 Skill。
2. 澄清：问题源于原始描述中的具体歧义，能指出答案如何影响图或行为。
3. 反例：用具体情境检验当前理解，不诱导选择“推荐规则”。
4. 范围：不增加审批、调度、自动重试等未确认业务；技术选择另行标明。
5. 停止：范围可以准确表达后进入实现，不用整图额外审批或重复问答拖延。
6. 图：来源关系和数据连接区分；权限、类型、端口条件与实际函数和值关联；设计未知不冒充事实。
7. 实现：实际创建/派生/配置/传输，失败不产生被禁止的效果；检查采用独立预期与实际存储结果。
8. 维护：独立状态模块、源码扫描、探针、严格模型检查、收尾门禁、关闭采集的业务不变性。
9. 迭代：用户改变规则后，同一图更新、保留稳定身份，旧验收失效，重新运行检查。
10. 可审查：保留原始对话、过程失败与修复、运行证据、图和截图，说明模拟测试的限制。

单个对话通过不能证明任何模型、任意需求都不会跑偏；一次截图也不能证明运行映射完整。脚本结果只覆盖明确的项目和场景。

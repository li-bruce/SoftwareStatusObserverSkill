# 发现、修复与复测

原评估反例的修复进入 [tools/test_refactor.py](../../../tools/test_refactor.py)，原审查脚本和结果不改写。以下记录本轮实际遇到的问题，不将测试脚本自身的问题算成产品缺陷。

| 问题 | 修复 | 验证 |
|---|---|---|
| 独立模块漏检无效声明、资源负数，布尔值混同整数 | 共同协议校验；保留非法运行事实并诊断 | 声明入口对照、类型及实际配置反例 |
| 父状态上的迁移被扁平匹配误报 | 按声明父子关系匹配，子级处理优先，条件不满足回退父级 | 与真实 HierarchicalMachine 迁移比较 |
| 两套查询不一致；未授权等待实例缺失 | 同源实例投影；交付示例在授权前建立真实运行记录 | 实际存储对照、等待实例、统一导出 |
| 独立目录有执行器，但调度/停止/恢复仍在业务服务 | 完整迁移协调机制，保留事务和领域接口 | 30 个旧新 SQLite/工作线程场景；执行器对照 |
| 空 probe_modes 或必需检查删除会静默弱化验证 | 非空配置、断言数、原检查约定保护 | 空模式、零断言、删除命令/探针反例 |
| 只查旧图，新增入口漏检 | 独立枚举源码与符号；新增文件必须映射或有理由排除 | 新文件不在图中、仅加入 watch 仍失败 |
| 监视器只比较文件哈希，登记/验收后仍保留旧任务；编辑中的配置错误终止监视 | 比较任务变化，配置暂时无效时报告缺口并重试；禁止空源码范围和关闭必要映射检查 | 实际 watch 进程经历漏登记、无效配置、修复、登记、验收 |
| 公共查看器复制后丢失归档项目的历史判断依据 | 用节点 basis_fields 与字段配置表达，移除名称推测 | 旧事件不使用未来版本/时钟；异领域字段测试 |
| 采集历史和因果引用无界 | 有界事件保留、日志轮换、引用上限、明确缺口 | 容量和过期测试；录制独立订阅保留全部区间事件 |
| 页面保存过早显示成功、冲突覆盖风险 | 服务确认后显示保存；修订比较与原子替换 | 重载、不同实例、写入失败和冲突测试 |
| 个人配置中的 JSON 字符串可夹带 NaN/Infinity 坐标 | 同时检查内层 JSON 的有限数值 | 三种非有限坐标拒绝，原文件不改 |
| 文档还写个人布局仅存浏览器 | 更新分层图、记录分析及独立模块说明 | 包内链接检查与实际重启恢复 |

测试流程也作了修正：澄清测试夹具只能继承未改变源码的既有分类；双方式例子的源码指纹在审核后重新生成；浏览器选择节点不能先用 Enter 展开再重复点击；回放应按所选粒度检查整个区间。首次跨工具进程访问本地服务器失败后，改为服务器与浏览器同次启动。这些不是用户程序运行缺陷。

绘图拆分后，生成文件检查按预期拒绝未重新登记的模板。核对规范源与复制产物后，记录明确的重新生成原因，再运行完整检查；没有删除这个检查来获得通过。

独立对话测试的失败、修复与最后一次运行另外保留，不能用仓库示例通过替代。

独立打印项目的首轮还发现了协议接入偏离：开发 AI 在独立目录里自写了同名 BOStateGraph、另一套导出和简化 SVG 页面。虽然项目业务测试能运行，这没有验证公共核心和完整图交互。候选 3 因此明确要求使用公共核心和图资产；gate 增加实际 `stategraph_export` 校验，旧简化格式和删去实例但重算摘要的反例均被拒绝。跨实例共享打印机的约束保留为项目扩展，不能为了通过公共单次运行资源池校验而改写业务。

这说明“目录存在”或“测试通过”不足以保证接入了正确模块，不能只通过加长提示词处理。新检查与独立试用修复共同作为本轮闭合证据。

候选 3 接入后又暴露出回放只依赖运行内活动日志的限制：普通 Python 状态和跨运行共享打印机没有适用的历史帧接口。候选 4 增加可选 `runtime_frames`，以事件 ID、进程、构建和事务修订绑定实际快照；公共记录器核对身份和范围，公共查看器显示状态、活动、共享资源的前后值。缺帧保持未知，不用结束状态回填。资源节点也不再假定一定存在 `machine.execution`。新增回归验证了跨进程拒绝、不可覆写历史、选定字段、共享资源和缺失快照。独立打印项目通过真实事务历史接入，而不是另写回放引擎。

发布前检查发现部分当前源码仍含 CRLF，而仓库要求 Git 检出为 LF。字节变化会使已验收指纹失效。因此先规范当前源码、再重新生成并验收；候选 5 与候选 4 只有五个文本文件的换行差异。冻结评估、试用证据和旧实现夹具明确保留原始字节，避免历史哈希被 Git 改写。

独立项目还在 390/320px 复现公共工具栏不换行导致的横向溢出。先前的项目 CSS 修复在候选 6 合并进公共 `viewer.css`，两个原有示例和独立项目共同复测；不要求每个新项目自行补同一个问题。

维护功能迭代中，把业务函数从 `bo_stategraph/workflow.py` 移到 `app/workflow.py`，触发了“删除探针”和“修改原白盒规则”的误判。候选 7 增加显式一对一 `source_moves`：验证原/现源码清单、保留人工图节点身份，仅重绑定源码位置；断言、参数、节点和事件阶段仍受原保护。三项回归包括合法移动、借迁移弱化检查、未知或歧义映射。保留旧路径不再作为规避办法。

独立项目的最终浏览器测试发现，全局管理事件在找不到任务时被适配器错误关联到最后一个任务。事件本身和管理员拒绝结果没有错，错误在实例投影。修复为保留管理事件自己的身份、任务状态为空，并新增原始 SQL 历史的独立对照。最终 29 项浏览器检查及 437 项映射见证通过，见 [记录](dialogue-trial/round-04/failures.md)。

三个隔离的业务错误副本没有修改原实现或预期。过期审批、尺寸边界、绕过维护分别被原规则检出；未同步源码时门禁先拒绝，正确重建映射后仍报告业务失败。这验证了两个结果的分离，不意味着映射检查应当修正业务值。

# 观测器自身事件排除 · 2026-10-23

已修复公共 Skill、两个内置示例，以及测试对话“安装 business-observer Skill”中的 `upload-review` 项目。观测代码仍接受源码归属和版本检查，但图轮询、源码查看、布局、记录控制及采集器汇报不作为业务步骤采集。登录、业务查询、通知、上传和审核保持原有记录。

## 原因和复现

试用项目的 HTTP 中间件对所有路由采集，未匹配到业务分组时默认归入 `developer`。原实现清单也将 12 个图接口列成必须采集的功能。源码展开则可能把已经排除的观测函数重新生成到图里。

隔离数据库中不做业务操作，只请求 `/api/view` 四次，产生了四条 `developer / graph_view` 事件。见[原始失败](failure-polling.json)。

## 修复范围

- 采集前识别图页面、图资源和图接口，取消未知请求自动归入“开发者图”的逻辑。纯观测辅助函数用 `bo_` 名称登记，源码扫描保留它们，业务图不展开它们。
- 公共采集器在载荷构造、写入和记录快照读取时抑制递归上报；上下文按线程和异步任务隔离，异常后恢复。真正的状态迁移和业务通知不能按名称过滤掉。
- 静态检查允许有实际路径证据的观测路由排除，仍拒绝排除登录等业务路由、混合路由和无法解析的动态路由。
- 原来误归业务的图接口采用明确审阅的迁移：原源码 AST 必须未变，全部来源必须确属观测路由。原业务参数、必需探针、映射与白盒断言不减。路由迁移和后续辅助函数整理分两次验收，记录均保留。
- Skill 增加“仅操作图不产生业务事件，再执行业务确认采集仍在”的验收要求。见[接入规则](../../../skills/business-observer/references/observer-exclusion.md)。

[新增 12 项回归](../../../tools/test_observer_noise.py)通过，覆盖递归抑制、任务隔离、异常恢复、静态调用展开、路径边界、错误排除拒绝、迁移保护及业务通知保留。

|---|---:|---:|---:|---|
| 开启 | 50 次，另含开始/结束记录 | 0 | 12 | 已通过，提交说明保留 |

业务路径包含登录、上传、向审核人发消息、查询消息和审核。检查实际存储的说明、状态，以及事件中的说明值；开始/结束记录本身不进入记录文件。见[HTTP 结果](upload-review/observer-noise-results.json)和[测试代码快照](upload-review/test_observer_noise.py)。快照用于审查，运行须在完整试用项目中执行。

## 当前页面和使用

试用服务已重启。打开或刷新 [运行图](http://127.0.0.1:8848/graph)，选择实时观察或新建记录。在线核对构建与已验收源码一致：连续读取图 11 次，事件总数保持 15，图中没有观测自身节点，记录中没有 `developer` 事件。见[在线检查](upload-review/observer-noise-live.json)及[最终页面](final-graph.png)。

历史记录保留原来的模型和事件，不改写为新版本。业务页面自身的文件列表、消息查询属于业务请求，仍正常记录；“零新增”指只进行观测器操作时。未扩展到任意外部采集器和所有动态调用。

复现公共检查：在仓库运行 `python tools/verify.py`。复现试用项目：在 `upload-review` 运行 `python tooling/test_observer_noise.py` 和 `python validate.py`。这次修改在本地完成，尚未推送 GitHub。

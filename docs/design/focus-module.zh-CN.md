# 独立局部图模块

[返回路线](roadmap.zh-CN.md) · [统一图契约](unified-graph.zh-CN.md)

状态：基础提取器已实现，见 [命令与格式](../../skills/vibelens/references/focus-and-sharing.md)。当前支持稳定节点锚点、关系过滤、预算、版本、运行选择、原关系边界、JSON/Markdown。下文的自然语言定位、分页索引、页面专用入口和语义编辑冲突属于后续接口设计。

## 职责

从完整图的指定版本选取与当前问题有关的内容，产生可解释的局部图、被折叠部分的边界、完整来源映射，以及可跳回原图的定位信息。对话、当前页面和离线导出使用同一份结果。

模块独立于 PixiJS、数据库和编码 Skill：不修改完整模型，不执行业务操作，不重新判定权限。它接收已经规范化的模型与证据。规则计算若有需要，由规则适配器返回带来源的结果，再作为输入展示。

建议拆分为纯提取逻辑、来源与边界校验、JSON/Markdown 输出、现有页面渲染适配四部分。大图通过索引读取，范围外的内容不强制载入。

## 输入

| 输入 | 含义 |
|---|---|
| 图身份 | project_id、model_revision、schema_version；可选对应源码/构建版本 |
| 问题与锚点 | 需求、规则、节点、场景、变更或一次运行/检查 ID |
| 观察目标 | 讨论规则、分析改动、解释运行、核对失败场景 |
| 展开策略 | 允许的关系类型、向上/下追溯范围、必须保留的节点和已展开分组 |
| 运行选择 | 指定 run_id / check_id / 参数版本；不选运行时仅展示定义和静态结构 |
| 预算 | 节点/边/展开深度/查询时间上限；不能用它隐瞒关键缺口 |
| 显示偏好 | 显示名称、备注、位置、固定点、视野；与语义内容分别存储 |

自然语言可以由 Skill 转成锚点和过滤条件，但提取器检查引用是否存在、类型是否匹配、版本是否可用。没有可靠锚点时报告无法定位，不由 AI 自行画一张没有身份对应的图。

## 输出

输出建议称为 `focus.json`，包含：

- `focus_id`、提取器版本、输入范围和来源版本。
- 保持原身份的节点/边；新增的摘要与边界节点使用视图命名空间。
- `mapping`：每个摘要对应哪些原节点/边，或在指定版本下可继续分页展开的引用。
- `boundaries`：被截断的输入、输出、判定条件、状态路径、资源或外部效果。
- `coverage`：范围内已读取内容、未展开内容、未解析内容、预算截断和证据缺口。
- `questions`：需要用户确认的规则或边界含义，以及影响的需求和节点。
- `links`：完整图中的对应位置与源码；不可用的链接明确标识。

最小结构示意：

```json
{
  "focus_id": "focus:delete-A-C",
  "base": {
    "project_id": "tree-example",
    "model_revision": "m12",
    "schema_version": "design-v1"
  },
  "selection": {
    "purpose": "explain_rule",
    "rule_ids": ["rule:delete-direct-child"],
    "entity_ids": ["entity:A", "entity:C"],
    "check_id": null
  },
  "nodes": [],
  "edges": [],
  "mapping": {},
  "boundaries": [],
  "coverage": {
    "definition_complete_for_selection": false,
    "runtime_evidence": "not_selected",
    "limits_hit": []
  }
}
```

这是结构说明，空数组不构成可交付局部图，也不能生成“已完整”的结论。运行解释另绑定具体检查和其数据依据。

## 提取与摘要规则

1. 固定模型版本；读取运行时还须固定运行身份。查询期间数据改变时保留原依据，或重新构建，不能拼接成一个未经说明的快照。
2. 从锚点沿有类型的关系选择内容。涉及判断时保留规则、关键输入和条件组合；涉及执行时保留入口、退出、等待、资源和效果边界。
3. 沿显式映射补充必要的上层业务意图和下层实现位置。调用图邻近搜索可以辅助选择，不能单凭一跳邻居认定全部业务影响。
4. 使用已声明的抽象映射折叠。对未声明的分组，只能标为视图分组，不宣称执行或语义等价。
5. 处理每条跨边界关系，保留方向、类型、来源，以及连接到何处。多输入条件保留 AND/OR/排除或汇合语义。
6. 返回来源和缺口。源模型没有记录的依赖不能凭空恢复；此时“范围完整”不能成立。
7. 校验结果再渲染。AI 可以润色解释文字，不能通过润色增加事实、移除条件或把未知改成允许。

## 边界应当如何显示

| 被折叠内容 | 局部图保留什么 |
|---|---|
| 范围外参数或关系 | 简短名称、类型、来源、是否已有本次值 |
| 范围外判断条件 | 条件身份、组合方式、本次是否求值；可展开入口 |
| 范围外后续操作 | 输出去向与效果类别，不暗示已执行 |
| 范围外活动/资源 | 等待/汇合要求、资源数量及其适用运行 |
| 未加载的大量实例 | 当前加载范围；只在总量已知时显示总数 |
| 动态或外部未解析内容 | 明确的未解析边界与原因 |

例如直接关系、群组成员和规则允许的递归继承都须保留各自的类型和依据。折叠中间节点后不能将路径冒充直接事实，也不能因为路径较长而删掉有效继承。OR 的备选分支、AND 的必要条件和排除操作数要分别保留；边界记录保存整条原始关系及其作用范围。当前提取器不生成推导捷径。

当某个 AND 条件被折叠，保留“还需满足范围外条件”的边界；不要让剩余条件看起来足以放行。折叠并行活动时，保留仍在运行/等待的活动数量和汇合规则；摘要状态的计算方法应明确，不能简单取最后一条事件。

预算不够时优先保留关键条件与边界，减少其他细节；仍不足时返回带缺口的视图，不报告完整解释。后续展开沿原版本和来源继续，重新选择最新版本是另一项显式操作。

## 对话和页面

- 对话先呈现本轮相关图与少量具体问题；已确认内容不再反复询问。
- 可用 Mermaid 或图片表达静态确认内容，同时提供相同 focus_id 的页面入口。静态图本身不宣称可拖拽或编辑。
- 当前页面继续采用同一套节点形状、连线、拖拽、算法布局、逐层展开和就地信息。
- 局部视图保留原节点；展开加入细节而不是换一张无关联页面。用户可返回完整图并定位。
- 个人位置与别名按稳定 ID 复用；局部独有的视野与摘要位置按 focus_id 保存。运行更新不重排手动节点。
- 展示内容区分需求候选、已确认定义、预览推导和真实运行；历史视图显示所属版本。

## 用户修改的处理

| 修改类别 | 处理方式 |
|---|---|
| 名称、备注、位置、展开 | 修改显示记录；保留原名和身份，不改变执行 |
| 规则、参数约束、转换或业务连接 | 生成包含 base_revision、节点/边 ID、需求依据和前后差异的修改建议；核对后更新候选规格与受影响场景，再交给编码阶段 |
| 对象当前值、实际关系或运行状态 | 不作为规格编辑直接写数据库；未来须经应用自己的命令与鉴权流程 |

语义修改只作用于明确选中的规则和范围。修改时完整图已更新，须定位冲突并重新核对，不能按旧局部图覆盖新规则。用户改变需求的决定与技术检查分开：后者通过不能替代前者，用户同意含义也不能替代程序测试。

## 必须验收的行为

| 编号 | 操作 | 预期 |
|---|---|---|
| F01 | 相同图版本、选择和策略重复提取 | 语义内容及来源映射一致，不依赖随机布局 |
| F02 | 分别提取直接、继承、群组、OR/AND/排除和上下文规则 | 原规则、方向、操作数和实例来源不变，不新增或取消权限 |
| F03 | 折叠一个 AND 条件或汇合前的活动 | 边界仍表明该条件/活动必需 |
| F04 | 提取过程中达到预算 | 明确截断；不把未读事实当不存在，不把缺口当通过 |
| F05 | 切换两个同时执行的检查 | 结果和输入不串用；历史不借用未来数据 |
| F06 | 使用旧 focus 修改已变化的规则 | 检出版本冲突，完整图不被覆盖 |
| F07 | 折叠、展开、刷新、返回完整图 | 相关稳定节点的标注、位置和身份保持 |
| F08 | 完整图存在源模型缺口 | 局部图保留缺口，不生成虚构连接 |
| F09 | 提取前后比较完整图和运行数据 | 提取器没有副作用 |
| F10 | 导出后在离线页面打开 | 图、边界和来源可读；没有运行证据时不显示实时状态 |

以上是待实现模块的验收要求，本轮未运行这些功能测试。
